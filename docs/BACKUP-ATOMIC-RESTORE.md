# 备份恢复的单文件替换保护

原恢复入口直接打开 `FileOutputStream(target)`，旧文件立即被截断。
后续 ZIP 校验或写入失败虽然会报告错误，原作品却已被破坏。
修复前的电脑回归确认：CRC 损坏会清空旧文件，截断输入会留下半份内容。

现在先写入目标同目录的随机临时文件，读完条目并校验 CRC、刷盘和关闭后，
再通过 Android `Os.rename` 原子替换。任何提交前错误都保留旧目标，清理本次临时文件；
不采用删除旧文件后重新复制的降级策略。同目录避免跨文件系统移动。
作品、自动保存、笔刷、纹理、参考图和字体共用此入口，原有冲突选项不变。

这是单文件保护，不是整包事务。前面的文件成功、后面的文件失败时，前者保留恢复结果。
进程被强制终止可能留下临时文件，但不会用半份临时数据覆盖原文件。
不改变备份格式，不处理笔刷存储格式遗漏或数位笔设置分类。

## 验证范围与待测项

JVM 测试调用实际备份/恢复入口，覆盖 CRC 错误、截断输入、提交失败、临时文件清理、
正常覆盖和保留副本。宿主通过真实 `Files.move` 原子替换，不能代替 Android `Os.rename` 真机验证。
本轮尚未完成真机回归，需要维护者补测后再判断是否合并：

1. 使用一次性工程，备份后修改内容，分别选择覆盖、跳过、保留两份，检查内容和数量。
2. 对同名一次性工程恢复 CRC 损坏或截断的备份，确认报错后原文件逐字节不变、仍能打开。
3. 对不存在的目标重复故障测试，确认没有半份作品或遗留的本次临时文件。
4. 检查自动保存、笔刷、纹理、参考图和字体的正常恢复，尤其是同名覆盖。
5. 有条件时模拟存储不足或写入失败，确认旧文件保留；不要用唯一原稿做故障测试。
